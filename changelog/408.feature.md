* Processing information is now fully supported: all dataset functions, including the
  composite source generator, record their changes with the input data points as parents,
  also at other time points, e.g. for fits. Functions whose results are not emissions
  data, like `count`, ignore it, and functions returning a DataArray raise on datasets
  with processing information.
* Added {py:meth}`xarray.Dataset.pr.processing_step` (a `with` block) and
  {py:func}`primap2.records_processing_step` (a decorator) to record processing steps in
  your own code. A changed value is computed from the old value by default, use
  `replaces=True` if it replaces the old value. Values set without inputs raise an error
  unless a `source` is given.
* Added {py:meth}`xarray.Dataset.pr.with_creation_step` and
  {py:meth}`xarray.DataArray.pr.with_creation_step` to start tracking processing
  information.
* Added {py:meth}`xarray.Dataset.pr.processing_info` and
  {py:meth}`xarray.Dataset.pr.with_processing_info` to separate the processing
  information from the data and to recombine them.
* Added `primap2.format_timeseries_history` to show the history of a whole timeseries.
* Added {py:meth}`primap2.ProcessingStepRecorder.computed_from` to record values computed
  from other time points, categories or variables in a processing step block.
* Selecting a list of variables with `ds.pr[[...]]` also selects their processing
  information.
* Added {py:meth}`xarray.Dataset.pr.used_sources` to look up which sources were used
  for each data point: 1 if the `source` of a step in the history of a data point
  is the source, also at other time points, else 0.
* {py:meth}`xarray.Dataset.pr.fillna` now also accepts a single value.
